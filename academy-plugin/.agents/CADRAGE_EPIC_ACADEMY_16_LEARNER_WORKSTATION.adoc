:statut: CADRÉ — décision pilote attendue (US-0 ✅, US-1→8 🟡)

== Contexte

L'arbitrage pilote du 2026-11-05 tranche la cible commerciale : **l'acheteur est
l'apprenant**, et commercial packaging appartient à **talaria.school**. Le
constat décisif est pédagogique, pas technique : le référentiel FPA exige du
candidat qu'il **produise** un SPG, un SPD, un storyboard et une **capsule
vidéo** pour son dossier technique (corpus FPA, pages 92/95 : « capsule
vidéo », « storyboard », « annexer le scénario pédagogique et le storyboard »).

Academy n'est donc pas une « boîte Moodle » : c'est le **poste de travail** où
l'apprenant produit les livrables de sa certification, assisté par un agent
(opencode) et un LLM (BYOK). Le manque actuel n'est pas le code de la boîte —
il est **livrable** : academy produit un installeur *dans le build d'un
consommateur Gradle*, pas un artefact que talaria peut remettre après `PAYE`.

== Constats (audit S-023 — faits vérifiés)

. *L'acheteur est l'apprenant* (arbitrage pilote S-023). Il doit produire les
  livrables de certification — pas seulement consommer un PDF/MP4.
. *Aucun artefact distribuable.* `GenerateInstallerTask` écrit dans
  `build/academy/installers/` du **build consommateur**. Il n'existe pas de
  `academy-workstation-<version>.zip` pré-construit à remettre à un acheteur.
  Le dogfooding (`dogfood/build/academy/installers/linux/install.sh`) le prouve :
  l'artefact est un *script généré localement*, pas un livrable.
. *La boîte est vide sans matériel.* `MaterialReadiness.Empty` par défaut,
  `materialDir` = `material/` ; le matériel est produit par `training` (gate
  corpus G1→G5). Academy **consomme**, ne produit pas (frontière S-022).
. *L'outillage de production existe déjà.* `OpenCodeCatalog` (S-009) catalogue
  **11 plugins publics vérifiés** et `exposure()` lit le contrat N0
  `ToolExposure`. Les tâches existent (`generateSPG`, `generateSPD`,
  `generateDeckSlides`/`translateDeck`, `generateCapsuleVideo`,
  `bookPipeline`/`convertDocument`, `publishSite`). *Il manque le parcours
  guidé qui les enchaîne* — pas les tâches.
. *BYOK existe, mais le défaut est lourd.* `academy.byok` couvre 5+ providers
  (S-010), mais le compose embarque Ollama (Moodle + PostgreSQL + Ollama +
  Portainer). Sur une machine d'apprenant, le profil **cloud BYOK** doit être
  le défaut, Ollama l'opt-in.
. *Zéro documentation apprenant.* `find README*` = **0 fichier** dans
  `academy-plugin/`. Un candidat non-technique ne peut pas démarrer
  (`./gradlew generateLinuxInstaller` est un geste de développeur).
. *Windows non prouvé.* `ACADEMY-12-3` est ouvert alors que l'apprenant cible
  est très probablement sur Windows — un `.bat` généré n'est pas une preuve.
. *Aucun export de progression.* `SessionMemoryContract` est implémenté hors
  academy (codex `PgVectorSessionMemory`), `bridge_events` est local. La page
  `suivi` de talaria ne peut rien afficher sans un export consenti.
. *Le fulfillment talaria est P0 non tranché.* `T-FULFILLMENT US-0` compare
  quatre options — dont **(c) LMS academy/Moodle** — et n'a produit aucun
  contrat d'accès (jeton, expiration, e-mail).
. *Version publiée en retard.* Local `0.0.3`, Central `0.0.2` ; un zip livrable
  doit être versionné et **immuable**.

== Schéma du poste de travail

```
academy-workstation-<version>.zip
├── install.sh / install.bat        # 1 commande, idempotent, Docker only
├── README-apprenant.md             # 3 étapes + dépannage + limites
├── workstation-manifest.json       # versions + sha256 (vérifiable par talaria)
├── project/                        # Dockerfile, opencode.json, AGENTS.md
├── material/                       # module pilote (pivot EPIC K + AsciiDoc)
├── offline/                        # images docker save + manifest (opt-in)
└── compose/                        # Moodle + PostgreSQL + opencode + Portainer
                                    # (+ Ollama seulement si profil local)
```

À l'installation :

```
install.sh
  → provisionne Docker (Linux apt / macOS Colima / Windows WSL2+Desktop)
  → écrit $HOME/.academy/{compose,project,material,seed}
  → docker compose up -d
  → Moodle http://localhost:8080  +  module déjà injecté (moodle-material)
  → opencode / AGENTS.md : parcours SPG → SPD → slides → capsule → PDF
```

== Mise en œuvre S-024 (US-1 + US-2)

* `LearnerWorkstationManifest` + `WorkstationFile` (domaine pur, SHA-256, JSON déterministe, chemins relatifs sûrs) + tests de contrat.
* `BuildLearnerWorkstationTask` (`buildLearnerWorkstation`) : zip déterministe (entrées triées, timestamp ZIP epoch) — installateurs + `project/` + `material/` + `offline/` + README + manifeste.
* `OpenCodeToolGenerator` : un fichier `.opencode/tools/cccp.ts` avec un `tool()` par borough public **enabled** (version non vide) ; le wrapper exécute `gradle <task>` dans le workspace. Doc opencode vérifiée le 2026-11-05 (`.opencode/tools/`, filename = outil, `<file>_<export>`).
* `WorkstationProjectGenerator` : `settings.gradle.kts` + `build.gradle.kts` appliquant les plugins publics activés, versions vérifiées au catalogue workspace du 2026-11-05.
* `InstallerScriptGenerator` : l'installeur écrit aussi les outils + le projet (parité Linux/Windows).
* **Dogfooding réel** : consommateur `/tmp`, `buildLearnerWorkstation` → `academy-workstation-0.0.3+fpa-pilot-0.0.1.zip` (11 entrées), manifeste `sha256` vérifié, `build.gradle.kts` à 11 plugins, `install.sh`/`install.bat` câblés.
* **Correctif révélé** : le guide apprenant citait `./gradlew` alors que le workspace n'a **pas** de wrapper (l'image porte `gradle`) → `gradle` partout (guide + material guide).
* Gates : `compileKotlin`/`compileTestKotlin`/`validatePlugins`/`publishToMavenLocal` VERTS ; zéro test local (CI).

== Mise en œuvre S-025 (US-3 + US-4)

* `WorkflowGuideGenerator` : parcours FPA en 5 étapes (SPG/SPD **écrits par le candidat**, slides, storyboard+capsule, dossier PDF, diagrammes), outils `cccp_<borough>` et tâches exactes lues au catalogue ; le borough privé `training` est explicitement **non exposé**.
* `LearnerGuideGenerator` inclut le parcours dans `AGENTS.md` ; le README apprenant porte un résumé FR + pointe vers la section.
* `WorkstationProfileResolver` : `CLOUD_BYOK` (défaut) coupe Ollama et bascule sur **Ollama Cloud** si le provider configuré est encore le local ; `LOCAL_OLLAMA` conserve le runtime.
* `InstallerPlatform.ollamaEnabled` : `composeBody`/`envBody` conditionnels (service, volume, `OLLAMA_HOST`), parité Linux/Windows.
* `GenerateInstallerTask` et `buildLearnerWorkstation` utilisent le résolveur ; `OpenCodeConfig.localRuntimeEnabled` aligne le guide sur la pile réelle.
* **Dogfooding build** `/tmp` : zip `academy-workstation-0.0.3+fpa-pilot-0.0.1.zip`, manifeste `CLOUD_BYOK`, `opencode.json` `ollama-cloud` + `{env:OLLAMA_API_KEY}`, installeur sans aucune référence Ollama, `.env` `OLLAMA_API_KEY=`.
* **Changement de comportement assumé** : le profil par défaut passe à `CLOUD_BYOK` (D-LWA-5) → l'installeur n'embarque plus Ollama par défaut ; `workstationProfile.set(LOCAL_OLLAMA)` restaure ACADEMY-6.
* Gates : compiles/validatePlugins/ktlintCheck/publishToMavenLocal VERTS ; **CI à obtenir par le push**.

== Options écartées

|===
| Option | Raison du rejet
| (a) URL signée seule, sans poste de travail | Ne satisfait pas la production des livrables de certification (SPG/SPD/storyboard/capsule) — l'apprenant reste spectateur.
| (b) Poste hébergé (SaaS) | Viole « aucun VPS / mono-utilisateur » ; coût d'exploitation et support incompatibles avec 60 €/module.
| (c) Vendre le plugin Gradle seul | Un apprenant non-technique ne peut pas exécuter `./gradlew generateLinuxInstaller` ; ce n'est pas un produit.
| (d) DRM/licence dans academy | Apache 2.0 = forkeable ; le verrou reste dans la couche privée (orchestration/transaction).
| (e) Clé LLM bundlée | Coût LLM à ta charge + secret dans un artefact distribué — interdit.
| (f) Module uniquement généré par `training` | Bloque la v1 sur le gate G1→G5 ; le module pilote manuel prouve la chaîne sans cette dépendance.
|===

== Critères de sortie (Definition of Done)

. Un **zip** `academy-workstation-<version>.zip` est produit par `buildLearnerWorkstation`.
. Sur une **machine vierge + Docker**, `install.sh` (ou `install.bat`) démarre Moodle, injecte le module pilote et arme opencode en **< 15 min**, avec **une seule clé BYOK**.
. L'apprenant produit, **sans commande inventée**, un SPG → des slides → une capsule → un dossier PDF.
. `workstation-manifest.json` est vérifiable (`sha256` de chaque fichier).
. `academy-report.json` est exportable (opt-in, zéro télémétrie).
. **Windows** est prouvé par dogfooding réel (US-8).
. Zéro secret dans l'artefact ; zéro DRM dans academy.

== Ce que cet EPIC ne fait pas (non-goals)

* **Auteuriser le contenu** — c'est `training` (gate G1→G5) ; academy consomme.
* **Encaisser / gérer les droits** — c'est talaria (`T-PAYMENT`, `T-FULFILLMENT`) et la couche privée.
* **Multi-tenant / SaaS** — hors périmètre mono-utilisateur.
* **Migrer le bridge vers Spring Boot** (`ACADEMY-10`) — indépendant, non bloquant.
* **Audiodescription vidéo** (`GBL-011-4`) — dépendance de `capsule`, indépendante.
* **Publier sur Maven Central** — l'artefact livrable est le zip, pas le plugin.
