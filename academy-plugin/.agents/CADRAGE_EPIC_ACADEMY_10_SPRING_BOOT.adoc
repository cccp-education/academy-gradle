== Objet

L'EPIC ACADEMY-10 (cadré S-012) migre le bridge HTTP local livré en ACADEMY-8
(Ktor 3.2.0 Netty) vers **Spring Boot WebFlux + coroutines + R2DBC/PostgreSQL +
Jackson 3**. Ce document remplace les notes de cadrage S-012 par un dossier de
décision : faits vérifiés au 2026-11-02, conséquences sur le catalogue, options
écartées, découpage US et plan de migration fichier par fichier.

*Aucune décision n'est actée par ce document seul* : les choix structurants
(D-ACADEMY-10-1..12) restent à confirmer par le pilote (pattern S-057).

== 2. Ce qui ne change pas (invariants)

. **Le domaine pur `academy.bridge` reste verbatim** : `MoodleEvent`,
  `BridgeEventTranslator`, `BridgeRoutes`, `BridgeServerConfig`,
  `ByokBridgeSupport` ne connaissent ni Ktor ni Spring (D-ACADEMY-8-4). Seules la
  couche serveur et la tâche migrent.
. **Le bridge route et acquitte — il ne pense pas** (D-ACADEMY-8-6) : zéro LLM,
  zéro tâche Gradle, zéro écriture de fichier.
. **Anti-corruption `BridgeWire`** : les contrats N0 (`contracts.session.*`)
  restent purs ; le bridge mappe sa propre vue `@Serializable` au bord
  (D-ACADEMY-8-11).
. **Opt-in et local** (`bridgeEnabled=false`, host `127.0.0.1`, port `8765`,
  D-ACADEMY-8-2/8-7) ; aucun VPS, mono-utilisateur.
. **Surface HTTP** : `GET /health`, `POST /events/moodle`, `POST /session`
  (D-ACADEMY-8-6/9). Les schémas d'entrée/sortie ne changent pas.
. **Un seul chemin de code** entre production et tests (D-ACADEMY-8-10).

== 3. Décisions proposées (à acter)

[cols="1,4,2", options="header"]
|===
| ID | Décision proposée | Justification

| D-ACADEMY-10-1
| **Migrer vers Spring Boot 4.1.2** (dernière GA), pas 4.1.1 ni 4.2.0-RC1.
| C-4 : 4.1.2 = GA la plus récente, correctifs inclusifs ; une RC n'est pas une
  base de production. 4.1.1 est déjà dépassé.

| D-ACADEMY-10-2
| **Pas de plugin Gradle `org.springframework.boot`** : importer
  `platform("org.springframework.boot:spring-boot-dependencies:4.1.2")` dans le
  catalogue de l'academy et déclarer les starters. Le lancement reste
  `runApplication<AcademyBridgeApplication>(*args)` dans la tâche Gradle.
| Le plugin Boot veut un `bootJar`, un main class et un packaging applicatif :
  incompatible avec un **plugin Gradle** publié. Le spike prouve que le BOM +
  `runApplication` suffisent (C-7).

| D-ACADEMY-10-3
| **Aligner explicitement `kotlin-stdlib` sur 2.4.10** après l'import du BOM Boot
  (contrainte de résolution ou `kotlin.version` surchargé).
| C-8 : Boot gère 2.3.21, le compilateur est 2.4.10 ; sans alignement le stdlib
  peut régresser sous le compilateur.

| D-ACADEMY-10-4
| **Coroutines `suspend` pour les handlers** (`@RestController` +
  `suspend fun`), `kotlinx-coroutines-reactor` fourni par le BOM Boot.
| L'écosystème cccp est coroutine-first (koog/langchain4j adapters) ; WebFlux
  supporte nativement `suspend` (prouvé C-7). Les `Mono`/`Flux` restent au
  transport, pas dans le domaine.

| D-ACADEMY-10-5
| **`BridgeWire` migre de kotlinx-serialization à Jackson 3**
  (`tools.jackson.module:jackson-module-kotlin`), et `kotlinx-serialization-json`
  quitte le plugin si plus aucun code ne l'utilise.
| Le reste de l'écosystème JVM (codebase/codex) sérialise en Jackson ; un seul
  sérialiseur réduit la dette. Si le pilote préfère le statu quo, kotlinx reste
  possible (option écartée O-4).

| D-ACADEMY-10-6
| **Persistance R2DBC différée derrière un flag** : US séparée
  (`ACADEMY-10-5`, opt-in, défaut off), table `bridge_events`, DDL co-localisé.
| Le bridge doit d'abord migrer **iso-comportement**. La persistance sert
  Qualiopi (ACADEMY-9) et ne doit pas bloquer la migration. Les événements
  peuvent être journalisés plus tard sans changer la surface HTTP.

| D-ACADEMY-10-7
| **Réutiliser le PostgreSQL du compose** (`postgres:16`, ACADEMY-6), jamais un
  second service.
| La boîte a déjà PostgreSQL (D-ACADEMY-6-13) ; un doublon violerait l'économie
  d'encre et compliquerait l'installeur.

| D-ACADEMY-10-8
| **La tâche Gradle reste le lanceur** (`serveWebhookBridge`, daemon bloquant),
  avec un seam `serverLauncher` conservé. Un `main()` CLI peut être ajouté mais
  n'est pas la voie par défaut.
| D-ACADEMY-8-2 (artisan de build mono-utilisateur) ; la tâche est déjà testée
  (SKIPPED par défaut) et l'installeur/guide la documentent.

| D-ACADEMY-10-9
| **Pas d'authentification, pas de Spring Security, pas de Thymeleaf, pas de
  mail, pas d'Arrow** : hors périmètre (local, mono-utilisateur).
| D-ACADEMY-8-2 ; le draft `sources/draft/api` les avait, mais la vision academy
  les exclut.

| D-ACADEMY-10-10
| **Le POM publié n'embarque pas Spring Boot en dépendance transitive lourde
  côté consommateur** : les starters sont `implementation`, pas `api`.
| Un consommateur du plugin n'a pas à hériter de WebFlux ; le bridge est une
  fonctionnalité interne de la tâche.

| D-ACADEMY-10-11
| **Bump BOM MEMPHIS = décision séparée** (si et seulement si le pilote veut
  aligner le catalogue partagé sur Boot 4.1.2/Jackson 3). L'academy n'en dépend
  pas pour compiler.
| C-2/C-3 ; ne pas coupler une migration locale à 10+ boroughs.

| D-ACADEMY-10-12
| **Preuve = tests existants + nouveaux tests Spring** : `testApplication` Ktor
  est remplacé par `WebTestClient`/`@SpringBootTest` (ou un vrai `HttpServer`
  pour le functional), plus le dogfooding `curl` réel.
| D-ACADEMY-8-10 (un seul chemin) et Local = Build/Tests = CI.
|===

== 4. Options écartées

[cols="1,3,3", options="header"]
|===
| ID | Option | Raison de l'écart

| O-1
| **Conserver Ktor** (statu quo)
| Ne répond ni à l'exigence « Jackson 3 / un seul sérialiseur », ni à la
  cohérence coroutine-first ; Ktor 3.2.0 est déjà en retard (3.6.1). Le coût de
  migration est faible (424 lignes, domaine inchangé).

| O-2
| **Spring Boot 3.4.2** (celui du BOM partagé)
| Livre Jackson 2.18/2.21 et non Jackson 3 ; contredit l'exigence actée S-012.

| O-3
| **Spring Boot 4.2.0-RC1**
| Une RC n'est pas une base de production pour un artefact publié.

| O-4
| **Garder kotlinx-serialization pour `BridgeWire`**
| Possible, mais deux sérialiseurs dans le même plugin et un écart avec
  codebase/codex ; à rouvrir seulement si Jackson 3 pose un problème au spike.

| O-5
| **Appliquer le plugin Gradle Spring Boot**
| Packaging applicatif incompatible avec un plugin Gradle publié ; le spike
  prouve que le BOM suffit.

| O-6
| **Persister les événements dès la migration**
| Couple la migration à ACADEMY-9 et ajoute un flag/DDL avant d'avoir prouvé
  l'iso-comportement ; US séparée.

| O-7
| **Auth/JWT/Thymeleaf/mail/Arrow**
| Hors périmètre local mono-utilisateur (D-ACADEMY-8-2).
|===

== 7. Risques et parades

[cols="2,4,3", options="header"]
|===
| Risque | Impact | Parade

| `kotlin-stdlib` 2.3.21 imposé par Boot 4.1.2 vs compilateur 2.4.10 | Moyen
| Alignement explicite (D-10-3) + test qui imprime la version de stdlib résolue ;
  `compileKotlin`/`compileTestKotlin`/`compileFunctionalTestKotlin` verts.

| Réactivité/Netty change le comportement des routes | Faible
| Mêmes status codes et corps JSON ; BDD + functional ; le domaine reste pur.

| Jackson 3 change les noms de modules/paquets | Faible
| Spike validé (C-7) ; round-trip `BridgeWire` testé.

| `WebFlux` ajoute un gros graphe de dépendances au plugin | Moyen
| `implementation` (pas `api`) ; mesurer le POM publié et le jar ; si le poids
  est excessif, isoler le serveur dans un sous-module (option future).

| Le mode daemon `runApplication` bloque la tâche | Faible
| Le seam `serverLauncher` est conservé ; `onlyIf { bridgeEnabled }` ; test
  TestKit `SKIPPED` par défaut.

| Bump BOM cross-borough mal ordonnancé | Moyen
| Décision séparée (D-10-11) ; l'academy ne l'exige pas.

| Perte des tests Ktor existants | Faible
| Les mêmes contrats sont testés via `WebTestClient` ; ne pas supprimer un test
  sans son équivalent GREEN.
|===
