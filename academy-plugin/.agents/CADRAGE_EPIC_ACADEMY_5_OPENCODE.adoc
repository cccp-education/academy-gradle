== Contexte

ACADEMY-6 (installeur hybride multiplateforme) est **TERMINÉ (S-008)** : les
trois scripts (Linux/macOS/Windows) génèrent un scaffold compose complet
(Moodle + PostgreSQL + Ollama + Portainer), seedé data-only, directement
exécutable. Le service `workspace` (session zsh + opencode) est **différé**
(TODO `ACADEMY-5` dans `composeBody()`) car son image
`cccp-education/academy-workspace:latest` **n'existe pas**.

La vision (§ 3.3 `VISION_PIPELINE_FORMATION.adoc`) acte qu'academy expose
trois capacités au stagiaire : **Moodle LMS** (le cours, ✅ ACADEMY-6) +
**opencode** (l'agent) + **BYOK LLM** (ACADEMY-7). ACADEMY-5 branche
l'**agent opencode** : il expose les tâches Gradle `education.cccp` de
l'écosystème et fournit le guide d'apprentissage.

== Constats (audit S-009, état réel du code et du workspace)

. *Le TODO workspace est bloqué par une image inexistante* : le point
   d'insertion `# TODO ACADEMY-5` (`InstallerScriptGenerator.composeBody()`)
   attend un service `workspace` dont l'image `cccp-education/academy-workspace`
   **n'est nulle part** (grep cross-workspace : zéro Dockerfile, zéro CI de
   publication). Publier une image custom est un chantier infra (registry
   cccp-education, rebuild à chaque bump de l'écosystème) sans lien avec la
   mission « exposer opencode ».
. *`ghcr.io/anomalyco/opencode` est réelle mais **insuffisante*** (vérifié
   `docker manifest inspect` **et** `docker run` S-009) : l'image officielle est
   **Alpine-minimal** — ni `zsh`, ni `bash`, ni `git`, ni Java, ni Gradle
   (seul `/bin/sh`). Elle **ne peut pas** exécuter les tâches Gradle de
   l'écosystème, et ne satisfait pas « session zsh » (D-ACADEMY-1). La
   constatation invalide l'hypothèse « image officielle telle quelle ».
. *Base réelle du workspace = `gradle:9.7.1-jdk25`* (vérifié `docker run`
   S-009) : Ubuntu 26.04, root, `bash` + `git` + `curl` + `unzip` + `apt-get`
   présents, Java 25 + Gradle 9.7.1 inclus — **exactement** les pins
   documentaires de D-ACADEMY-6-10, et zsh installable par `apt-get`. C'est la
   base du `Dockerfile` workspace généré (D-ACADEMY-5-1 révisée).
. *`opencode.json` n'est généré nulle part* : le scaffold ACADEMY-6 s'arrête au
   compose + seed. Aucun fichier de configuration opencode n'est produit, alors
   que la vision (§ 3.3) en fait le point d'exposition des tâches Gradle.
. *Le contrat N0 est disponible mais partiellement dormant* :
   `runtime-contracts` (MEMPHIS N0, **publié Central 0.0.1**, BOM 0.0.47)
   contient `InteractionProtocol` (`fun nextTurn(current: FormationTurn):
   FormationTurn?`), `FormationTurn`, `FormationRuntimePort`, `SessionBootstrap`,
   `ByokLlmConfig`, `ToolExposure`, `SessionMemoryContract`, `LearnerProfile`.
   Le cadrage RUNTIME-AGENTIQUE (§ 6) tranche : **academy est l'implémenteur**.
   Mais `ToolExposure` lui-même est *data-only* (une règle `foundry/public/*`),
   pas un manifeste de tâches ; la boucle `FormationRuntimePort` exige un
   runtime LLM (BYOK, ACADEMY-7) qui n'existe pas encore.
. *L'écosystème des tâches Gradle est réel et cataloguable* (vérifié source
   S-009, jamais deviné — leçon S-007 `moodle:4.5`) : 12 boroughs publics
   exposent des tâches dans des groupes `education.cccp`. Les domaines
   fonctionnels de la vision (formation) sont : bakery `generateSite`,
   slider `generateDeck`/`generateDeckPipeline`, capsule
   `generateCapsuleVideo`, document `bookPipeline`/`generateDocument`,
   plantuml `generatePlantumlDiagrams`, graphify `collectAndVerify`.
. *`AGENTS.md` est le point d'ancrage opencode* (documentation officielle) :
   opencode découvre automatiquement `AGENTS.md` à la racine du projet. Le
   guide apprenant (comment lancer une formation avec l'agent) doit donc être
   généré dans le workspace, pas dans le plugin.
. *La frontière `ToolExposure` est un guardrail physique* : l'apprenant
   n'invoque que `foundry/public/*` ; `foundry/private/*` (training, edster,
   workspace) est hors périmètre. Le `opencode.json` généré doit donc
   **n'exposer que les plugins publics** et zéro secret.

== Options écartées

- **Publier `cccp-education/academy-workspace:latest`** (image maison
  Java+Gradle+opencode) : chantier infra (registry, CI, rebuild par bump
  d'écosystème) sans lien avec la mission, et redondant — l'image officielle
  opencode suffit, le toolchain Java/Gradle peut venir d'un second service
  ou du projet hôte. Écartée (D-ACADEMY-5-1).
- **Générer `opencode.json` avec un builder JSON typé** (Jackson/kotlinx) :
  ajoute une dépendance compile pour un fichier de ~20 lignes déterministes
  (Loi de l'Économie d'Encre + D-ACADEMY-6-8). Écartée (D-ACADEMY-5-3).
- **Implémenter `FormationRuntimePort` maintenant** : exige BYOK (ACADEMY-7)
  + bridge Ktor (ACADEMY-8) + un LLM réel ; la machine serait non
  exécutable sans eux (leçon S-007). Écartée, séquencée (D-ACADEMY-5-8).
- **Exposer les tâches `foundry/private`** (training `generateSPG`/`generateSPD`) :
  contredit le guardrail `ToolExposure` (frontière physique public/privé,
  CADRAGE_EPIC_RUNTIME_AGENTIQUE § 6). Écartée.
- **Modifier le `opencode.json` global du pilote** : le fichier appartient à
  la machine de dev (`/home/cheroliv/workspace/opencode.json`, hors repo) ;
  academy génère son propre fichier dans le workspace apprenant. Écartée.
