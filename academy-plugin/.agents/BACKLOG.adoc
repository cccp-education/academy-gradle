'''
== Vision actée (S-002, arbitrage pilote)

Le borough Bagdad (academy-gradle) livre une **ressource autonome** qui contient tout ce dont l'apprenant a besoin pour expérimenter la formation du pipeline cccp.education :

```
┌─────────────────────────────  HOST  ─────────────────────────────┐
│  Docker        (socle conteneurs)                                │
│  Java Temurin 25 + Gradle 9.7.1  →  lance les plugins            │
│      education.cccp (bakery, document, slider, capsule, ...)     │
└──────────────────────────────┬───────────────────────────────────┘
                               │ docker compose
┌───────────────────────────── ▼  DOCKER  ─────────────────────────┐
│  Moodle 4.x  (LMS formation, cours seedé)                        │
│  MariaDB     (base Moodle, volumes persistants)                  │
│  workspace   (session zsh + opencode via conteneur)              │
└──────────────────────────────────────────────────────────────────┘
```

- L'installeur par plateforme (sh / bat) provisionne l'hôte, télécharge les dépendances, génère le `docker-compose.yml`, seede la base Moodle et les volumes, et génère `opencode.json` exposant les tâches Gradle de l'écosystème.
- `opencode` fonctionne hôte OU conteneur : il déclenche les tâches Gradle `education.cccp` sur le projet de l'apprenant (les plugins sont consommés depuis Maven Central + Gradle, zéro VPS).
- Rôle produit : **distribution** de la machine d'expérimentation (ne réplique pas KINSHASA — provisionnement dev ; KINSHASA reste N0).
