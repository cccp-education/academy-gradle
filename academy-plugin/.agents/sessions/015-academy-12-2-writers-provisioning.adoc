scripts générés et câble la sonde côté build.

== Constats (audit S-015 — faits vérifiés, jamais supposés)

. *L'installeur ne provisionnait rien* — `linuxScript`/`macosScript` se
   contentaient de *vérifier* `command -v docker` puis d'abandonner
   (`exit 1`) ; `windowsScript` vérifiait Docker Desktop via PowerShell sans
   jamais l'installer. Aucun OS n'était réellement provisionné.
. *Les deux scripts Unix étaient des quasi-doublons* — `linuxScript` et
   `macosScript` dupliquaient l'intégralité de la queue (compose + `.env` +
   seed + opencode + material), seule la 5-ligne de bootstrap différait. Seul
   `composeBody()` était partagé. La règle D-ACADEMY-12-5 (« un seul
   `install.sh` ») n'était **pas** appliquée.
. *La procédure Docker officielle est le dépôt apt, pas le script de
   convenance* — `docs.docker.com/engine/install/{ubuntu,debian}/` (vérifié
   S-015) : clé GPG `download.docker.com/linux/<distro>/gpg`, dépôt signé, puis
   les 5 paquets `docker-ce`, `docker-ce-cli`, `containerd.io`,
   `docker-buildx-plugin`, `docker-compose-plugin`. Le script `get.docker.com`
   n'est « not recommended for production ».
. *Docker Desktop Windows est scriptable et per-user* —
   `docs.docker.com/desktop/setup/install/windows-install/` : l'installeur
   supporte `install --user --quiet --accept-license --backend=wsl-2` ; le mode
   per-user **ne requiert pas** les droits admin. `wsl --version` / `wsl
   --status` sonde WSL2 ; `wsl --install` l'active (admin + reboot possible).
. *Colima est l'équivalent libre sur macOS* — `brew install colima docker` puis
   `colima start` ; jamais Docker Desktop (matrice S-014).

== Décisions respectées (S-014, non rediscutées)

Matrice d'engine par OS (Linux natif / Windows Docker Desktop / macOS Colima),
Portainer partout, décision pure vs sonde adapter, verdict sealed jamais jeté,
contrainte reboot assumée (installateur idempotent/resumable), un seul
`install.sh` (en-tête par OS, queue commune), frontière de test explicite.

**Ajustement D-ACADEMY-12-3 appliqué** : le task `checkContainerEngine`
**rapporte** le verdict sans jamais jeter. Un hôte non provisionnable est un
**verdict**, pas une exception — sinon un `check` échouerait sur un hôte nu
(contredisant le P0 S-014 et la KDoc du domaine). La tâche *constate*
(adapter), le script *provisionne* à l'installation.

== GREEN

* **`install.sh` unique et portable** (`unixScript`) : en-tête par OS
  (Linux = dépôt apt officiel ; macOS = Colima via Homebrew), **queue commune
  verbatim** (`appendComposeScaffold`). D-ACADEMY-12-5 appliquée par
  construction — un test asserte l'égalité de queue.
* **`install.bat` refondu** : sonde admin (`net session`) + WSL2
  (`wsl --status`) en **faits** (`IS_ADMIN`), puis `:bootstrap_wsl2`
  (`wsl --install`, resumable) ou `:install_docker_desktop`
  (`--user --quiet --accept-license --backend=wsl-2`), ou message
  `needs administrator rights`. Le contrat « vérifie seulement » est mort.
* **Port `EnvironmentProbe`** (fun interface) + **adapter `HostEnvironmentProbe`**
  (seul `ProcessBuilder` de la prod, timeout, échecs → fait `false`) +
  **`HostOs.fromOsName`** (mapping pur) + **task `checkContainerEngine`**
  (adapter injectable, défaut sonde réelle) câblée à `check`.
* **Functional TestKit** : scripts réellement écrits sur disque avec le
  provisionnement, `checkContainerEngine` **SUCCESS** sur hôte nu, `bash -n`
  réel sur les scripts Unix.
* **BDD** : `academy_installer.feature` 24 scénarios (+4), `AcademyEnvSteps`
  inchangé (7 scénarios `@env`).
