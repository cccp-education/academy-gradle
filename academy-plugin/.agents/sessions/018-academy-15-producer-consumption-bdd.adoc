== BS-1 — TDD RED : couverture et agrégation

Nouveau `ProducerReportInspectorTest` (6 unit) :

- un rapport qui ne couvre que `HTML` laisse un `PDF` **non vérifié** ;
- **tous** les rapports du matériel contribuent (findings + limites) ;
- un rapport malformé **ne masque pas** un rapport valide ;
- un rapport uniquement malformé laisse les livrables textuels non vérifiables ;
- un `kind` inconnu ne vérifie **jamais** un livrable ;
- une règle inconnue est conservée, une sévérité inconnue dégrade en `WARNING`.

*RED prouvé par compilation* : `Unresolved reference 'PRODUCER_REPORT_INCOMPLETE'`.

== BS-2 — GREEN : `ProducerReportInspector`

- Nouvelle règle stable `A11yRules.PRODUCER_REPORT_INCOMPLETE`
  (`producer-report-incomplete`).
- **Agrégation multi-rapports** : chaque `a11y-report.json` /
  `accessibility-report.json` sous le matériel est lu ; les rapports malformés

- Tolérance conservée : champs/règles/types inconnus ignorés, sévérité inconnue

== BS-5 — Dogfooding cross-borough réel

Deux builds séparés sous `/tmp/opencode/academy-a11y-dogfood/` (producteur et
consommateur — les deux plugins ne peuvent pas partager un classpath à cause du
pin `org.jetbrains:annotations` de la BOM `document` ; séparer est aussi le
modèle réel) :

. `producer/` applique `education.cccp.document:0.0.29` et exécute
  `reportDocumentAccessibility` sur un HTML réellement déficient
  (sans `lang`, `img` sans `alt`, table sans `th`, pas de `h1`) → **4 findings**
  écrits dans `build/docs/document/a11y-report.json`.
. `consumer/` applique `education.cccp.academy:0.0.2` (mavenLocal du HEAD) et
  exécute `auditTrainingAccessibility` sur ce dossier → **8 findings** :
  4 producteur agrégés + 3 vidéo (`demo.mp4` sans compagnons) +
  **1 `producer-report-incomplete`** pour `cours.pdf` (présent mais non déclaré).
. Rapport supprimé → `producer-report-missing` pour chaque livrable textuel
  (preuve de non-régression du chemin nominal).
. Rapport restauré → verdict `DEGRADED` de bout en bout, limites déclarées.

*Preuve* : la chaîne producteur → rapport → consommateur fonctionne avec le
**vrai** artefact `document`, pas avec une fixture inventée.

== Leçons

- Un rapport producteur **présent** ne vaut pas vérification : sans contrôle de
  couverture, la porte d'accessibilité produisait un « vert » non mesuré.
- Séparer producteur et consommateur en deux builds est le modèle réel et évite
  un conflit de classpath ; le dogfooding cross-borough reste possible en local
  (`mavenLocal`).
- La pyramide complète (unit + functional + Cucumber) trouve des angles morts
  différents : le functional a validé l'opt-in `SKIPPED` que le test unitaire
  `ProjectBuilder` ne peut pas prouver.
