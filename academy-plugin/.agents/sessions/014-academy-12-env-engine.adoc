== Mission

Demande pilote : créer un EPIC pour tester l'installation sur Windows via le
runner GitHub, puis — après audit — réaliser le test sur un **environnement
Windows réel** et chercher à installer **Docker Engine sans Docker Desktop**.

Le cadrage a recadré la demande : Docker Engine natif Windows ne fait pas
tourner les images Linux, et « sans WSL » est impossible. La matrice d'engine
par OS a été actée avec le pilote (Linux natif / Windows Docker Desktop /
macOS Colima), Portainer partout.

== Constats (audit S-014 — faits vérifiés, jamais supposés)

. *Docker Engine natif Windows ne fait pas tourner les images Linux* —
   `docs.docker.com/engine/install/` : « Docker Engine is also available for
   Windows... through Docker Desktop ». Le moteur natif ne voit que le noyau
   Windows. Or Moodle/PostgreSQL/Ollama/Portainer sont des images Linux.
. *« Sans WSL » sur Windows est impossible* — Docker Desktop exige WSL2 (ou
   Hyper-V) ; il *cache* WSL, ne le supprime pas. Activation admin unique +
   reboot possible.
. *L'installeur Docker Desktop est scriptable* —
   `install --user --quiet --accept-license --backend=wsl-2`. Licence gratuite
   pour l'éducation / OSS non-commercial (éligibilité cccP-education).
. *Docker Engine « sans Desktop » n'existe pas sur macOS* — Engine dépend du
   noyau Linux, VM obligatoire. Équivalent libre : **Colima** (MIT).
5. *La portabilité vit dans le CLI* — une fois l'engine démarré, Linux/macOS
   partagent `docker` + `docker compose` ; seul le bootstrap diffère (5 lignes).
6. *Colima tourne aussi sur Linux* — bootstrap unique possible mais impose une
   VM sur un OS où Docker natif existe. Écarté.
7. *D-ACADEMY-6-12 était une erreur de catégorie* — « Portainer remplace
   Docker Desktop » : Portainer est une GUI, pas un moteur. C'est l'engine qui
   se choisit.
8. *Le build est cassé sur un hôte nu* — `settings.gradle.kts:23` faisait
   `error("ossrhUsername not found")` : prouvé `./gradlew help -Duser.home=/tmp/faux`
   → `BUILD FAILED`. **Les 25 boroughs** partagent ce pattern, aucun n'a de garde.

== Décisions (cadrage `CADRAGE_EPIC_ACADEMY_12_WINDOWS.adoc`, D-ACADEMY-12-1..8)

Structurantes : **matrice d'engine par OS** (Linux natif / Windows Docker
Desktop / macOS Colima), **Portainer partout** (uniformité apprenant), ce qui
**supersede D-ACADEMY-6-12** ; décision **pure** (`DockerStrategyDecider`) vs
sonde (adapter) ; verdict sealed jamais jeté ; **contrainte reboot assumée**
(installateur idempotent/resumable) ; **un `install.sh` portable** + queue
commune ; **frontière de test explicite** (décision testable sans machine,
dogfooding OS réel) ; **P0 : `settings.gradle.kts` tolérant** ; `HostOs` dédié
(pas de couplage à `installer.TargetOs`).

== Note de clôture — méthode

La demande initiale (« runner GitHub Windows ») a été **écartée par les faits** :
les runners ne fournissent que des conteneurs Windows, aucune preuve
d'installation réelle. Le cadrage a évité de livrer un job CI vert qui ne
prouverait rien (leçon S-007 appliquée à l'infrastructure).

La règle du **delta source** a été appliquée à l'ouverture (compilation seule).
Le RED a été prouvé statiquement (compilation) à chaque palier, y compris au
niveau BDD (retrait temporaire de la glue). Le **P0** transforme un `BUILD
FAILED` en `BUILD SUCCESSFUL` sur un hôte nu — préalable indispensable au test
Windows réel (US-12-3).

_Reste ouvert_ : ACADEMY-12-2 (writers + sonde adapter) et ACADEMY-12-3
(dogfooding Windows réel) — le domaine pur est livré et prouvé, l'exécution par
OS suit.
