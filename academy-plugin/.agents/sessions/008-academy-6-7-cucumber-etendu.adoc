== Mission

Suite de l'EPIC ACADEMY-6 (installeur hybride), ordre acté **1 → 6 → 5 → 7**.
US : **ACADEMY-6-7** — Cucumber BDD étendu (contenu OS, compose, idempotence,
erreurs, opencode.json).

Mission tenue, et élargie d'un constat d'audit : le « contenu OS » asserté par
les tests était **contradictoire avec D-ACADEMY-6-10** (hôte = Docker
uniquement). Le scaffold émettait encore le provisioning hôte Java Temurin +
Gradle (héritage S-003), jamais retiré. La session a donc :

. étendu le BDD (6-7) au contenu OS, aux chemins, au marqueur d'idempotence,
   aux erreurs et à l'opencode.json différé ;
. **aligné le contenu OS sur D-ACADEMY-6-10** (hôte = Docker only) ;
. absorbé ACADEMY-6-1/2/3 (raffermissement hôte) qui devenaient caducs.

== Constats (audit d'ouverture)

. *Contradiction gouvernance/code* : D-ACADEMY-6-10 (révision pilote S-004)
   tranche « l'hôte ne provisionne **rien d'autre que Docker** — Java/Gradle
   vivent dans l'image workspace ». Or `InstallerScriptGenerator` émettait
   toujours `JAVA_HOME`, `temurin`, `services.gradle.org`, `setx JAVA_HOME`,
   `brew install openjdk@/gradle` (code S-003 jamais retiré).
. *Le prompt de reprise le signalait* : ACADEMY-6-1/2/3 « partiellement
   caducs pour le provisioning hôte Java/Gradle (D-ACADEMY-6-10) — à
   recadrer, voire à absorber dans le seul bootstrap Docker ».
. *Le BDD était incomplet sur le contenu OS* : pas de scénario sur l'absence
   du provisioning hôte, les chemins de staging, le marqueur versionné,
   les erreurs « Docker requis », ni l'`opencode.json` différé.
. *Le functional ne vérifiait pas* que les scripts générés étaient exempts de
   tout provisioning hôte.

== Décision de session

*Absorber ACADEMY-6-1/2/3 dans le seul bootstrap Docker.* Une fois D-6-10
appliqué, le raffermissement par plateforme (arch aarch64, persistance
PATH/JAVA_HOME, profil Windows 64-bit, Rosetta macOS) n'a plus d'objet :
rien n'est installé sur l'hôte hormis Docker. Les trois US sont marquées
**✅ CADUQUE (S-008)**.

== GREEN (prouvé)

`InstallerScriptGenerator.kt` — les 3 scripts n'émettent plus aucun
provisioning hôte :

* Linux : `docker` est l'unique exigence hôte (`command -v docker` sinon
  `exit 1` avec message actionnable) ; suppression du bloc Temurin
  (curl+tar) et du bloc Gradle (curl+unzip) ; `JAVA_VERSION`/`GRADLE_VERSION`
  restent déclarés comme **pins documentaires** de l'image workspace.
* Windows : garde admin `net session` conservée, check `Get-Command docker`
  suivi de `if errorlevel 1 exit /b 1`, suppression des downloads
  `adoptium`/`services.gradle.org` et des `setx JAVA_HOME`/PATH.
* macOS : Docker Desktop via Homebrew **conditionné** à l'absence de Docker
  (`command -v docker`), plus d'`openjdk@`/`gradle` brew, zéro `sudo`.
