== US-3 — parcours de certification

`opencode/WorkflowGuideGenerator.kt` :

* 5 étapes, avec les outils `cccp_<borough>` et les tâches lues au catalogue :
  1. **SPG/SPD** — écrits par le candidat en AsciiDoc (templates `material/`),
     revus avec l'agent. **Aucune tâche Gradle** : c'est la production évaluée
     par le jury.
  2. **Slides** — `cccp_slider` (`generateDeck`, `generateDeckPipeline`, …).
  3. **Storyboard + capsule** — `cccp_capsule` (`generateCapsuleVideo`, …).
  4. **Dossier PDF/EPUB/HTML** — `cccp_document` (`bookPipeline`, `assembleBook`, …).
  5. **Diagrammes** — `cccp_plantuml`.
* Le borough privé `training` est explicitement **non exposé** : le guide ne
  cite jamais `generateSPG`/`generateSPD` comme exécutables.
* Injecté dans `AGENTS.md` (`LearnerGuideGenerator`) ; le README apprenant porte
  un résumé FR et pointe vers la section.

== US-4 — profils BYOK

`workstation/WorkstationProfileResolver.kt` :

* `LOCAL_OLLAMA` → `OLLAMA_LOCAL`, endpoint local, pas de clé, Ollama activé.
* `CLOUD_BYOK` → Ollama désactivé ; si le provider configuré est encore le local,
  bascule vers **`OLLAMA_CLOUD`** (`https://ollama.com/v1`, `OLLAMA_API_KEY`),
  sinon conserve le provider/la clé configurés.
* `InstallerPlatform.ollamaEnabled` : `composeBody`/`envBody` conditionnels
  (service, volume `ollama-models`, `OLLAMA_HOST`, port 11434) — parité
  Linux/Windows.
* `OpenCodeConfig.localRuntimeEnabled` : le guide décrit la pile réelle
  (cloud = « clé fournie par vous », local = « Ollama »).
* `GenerateInstallerTask` et `buildLearnerWorkstation` utilisent le résolveur ;
  `workstationProfile` est la source unique (plus de dérivation depuis le
  provider).

== Changement de comportement assumé

Le profil par défaut passe à **`CLOUD_BYOK`** (D-LWA-5) : l'installeur n'embarque
plus Ollama par défaut, et `opencode.json` pointe sur `ollama-cloud` avec
`{env:OLLAMA_API_KEY}`. `workstationProfile.set(LOCAL_OLLAMA)` restaure le
comportement ACADEMY-6 (runtime local).
