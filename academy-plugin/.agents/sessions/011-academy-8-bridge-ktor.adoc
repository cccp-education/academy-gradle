== Constats (audit d'ouverture S-011 — faits vérifiés, jamais supposés)

. *Le « bridge opencode » existant n'est PAS HTTP.* `SessionProtocolDaemonTask`
   (codebase N1) est un daemon **stdin/stdout JSON-lines**. La justification de
   la vision § 8 D4 (« le bridge existe déjà ») est donc **inexacte** : Ktor est
   un transport **additionnel**, pas un remplacement (D-ACADEMY-8-1).
. *Moodle n'a aucun webhook natif* : le cœur expose des web services que l'on
   *appelle*, pas d'événement sortant. Un webhook exige un plugin tiers
   (`local_webhooks`), **absent de l'image** `erseco/alpine-moodle:v5.2.3`, et
   dont le payload n'est pas vérifiable S-011 (moodle.org → Cloudflare).
   → Décision : le schéma d'événement est **propre à academy** (`MoodleEvent`),
   aucun format tiers figé (leçon S-007 `moodle:4.5`) (D-ACADEMY-8-5).
. *Ktor 3.2.0 disponible et aligné* (Central vérifié) : core, netty,
   content-negotiation, serialization-kotlinx-json, **test-host** (tests sans
   port réel).
. *Les contrats N0 ne sont pas `@Serializable`* : `contracts.session.*` sont
   purs, sans dépendance de sérialisation (découverte en GREEN : `Serializer for
   class 'SessionResponse' is not found`). → **Anti-corruption layer**
   `BridgeWire` : le bridge ne réannote pas le contrat partagé, il mappe sa
   propre vue `@Serializable` au bord.
. *`opencode-session-contracts` n'est pas transitif* (`runtime-contracts` le
   déclare en `implementation`) → déclaré explicitement (RED n°1).

== RED (prouvé en 3 temps)

1. `Unresolved reference 'session'` — `opencode-session-contracts` non
   transitif, dépendance manquante.
2. `Unresolved reference 'BridgeEventTranslator'/'MoodleEvent'/'BridgeRoutes'`
   — domaine absent (compilateur Kotlin = RED statique).
3. `Unresolved reference 'bridgeEnabled'/'bridgeHost'/'bridgePort'` puis

Un **RED de comportement** a aussi été atteint en GREEN : le serveur levait
`Serializer for class 'SessionResponse' is not found` — le contrat N0 n'est pas
sérialisable, ce qui a **prouvé** la nécessité de l'anti-corruption layer.

== GREEN (prouvé)

* Domaine pur `education.cccp.academy.bridge` : `MoodleEvent` (schéma academy,
  payload opaque), `BridgeEventTranslator` (objet pur → `SessionPrompt` N0,
  **session id stable** via `UUID.nameUUIDFromBytes` — rejouable, pas
  d'aléatoire), `BridgeRoutes` (table unique `/health`, `/events/moodle`,
  `/session`), `BridgeServerConfig`, `BridgeWire` (anti-corruption),
  `ByokBridgeSupport` (provider id + description des routes).
* Serveur Ktor `WebhookBridgeServer` : `installBridge(Application, config)`
  (module unique, installé par le test **et** la production), `startBridge`
  (Netty, daemon bloquant, pattern `SessionProtocolDaemonTask`), réponses
  `BridgeAck`/`BridgeHealth`, rejets 400/404.
* Wiring : extension +3 properties, `InstallerPlatform` +3 champs,
  `GenerateInstallerTask`, tâche `ServeWebhookBridgeTask`
  (`@DisableCachingByDefault`, `onlyIf { bridgeEnabled }`, seam
  `serverLauncher` pour les tests, pattern codex `storeOverride`),
  `LearnerGuideGenerator` section bridge conditionnelle + `BridgeGuide`.

== REFACTOR + Dogfooding (preuve réelle — leçon S-007)

`publishToMavenLocal` + consommateur transitoire `/tmp` (pattern Règle 2),
serveur lancé par la tâche Gradle sur le port 8791, interrogé au `curl` réel :

* `GET /health` → `{"status":"up","provider":"ollama","model":"gpt-oss:120b-cloud"}`
* `POST /events/moodle` → `202`-style ack `status COMPLETED`, session id
  **stable** (rejouable), `eventName` en écho ;
* `POST /session` → ack `COMPLETED` ;
* corps JSON invalide → **HTTP 400** ; route inconnue → **HTTP 404** ;
* arrêt propre (processus tué, port libéré).

décision D4 (`VISION_PIPELINE_FORMATION.adoc` § 8 « le bridge opencode existe

additionnel** (D-ACADEMY-8-1), pour ne pas laisser une prémisse fausse guider
la suite.
