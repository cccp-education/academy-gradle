== Dogfooding (preuve réelle — leçons S-007/S-012)

Deux runs réels de Moodle 5.2.3 + PostgreSQL 16 via l'image préconstruite :

. **Test des outils natifs** : `moosh course-create -f ... -r` → cours créé
   puis **« exists. Skipping »** (idempotence prouvée) ; `section-config-set -s`
   → nom de section posé ; `activity-add -n -s <type> <id>` → `label`/`page`/`quiz`
   créés (vérifiés en base `mdl_course_modules`).
. **Dogfooding bout-en-bout du script GÉNÉRÉ** : consommateur transitoire
   `/tmp` (pattern Règle 2) + `publishToMavenLocal`, `generateMoodleImport` →
   `plan.json` + `ingest.sh`, puis application **réelle** du script dans un
   Moodle installé → cours `formation-fpa`, sections `01_accueil`/`02_coeur`,
   activités `forum`/`label`/`quiz`/`page`/`page`, contenu de page réel.

**Trois bugs réels attrapés par le dogfooding** (aucun couvert par un test vert) :

. `SHORTNAME=""formation-fpa""` — double guillemet (le `shellQuote` ajoutait
   déjà les quotes) → shell invalide. Correctif + test de régression
   `the applicator declares the course identity exactly once-quoted`.
. `awk -F'"' '$4==s'` — mauvais champ du CSV `moosh course-list` (le shortname
   est en position 3, CSV `"id","category","shortname",...`) → `could not
   resolve course`. Correctif `awk -F'","' '$3==s'`.
. `label` attend `--intro`, `page` attend `--content --contentformat` — mon
   premier rendu posait `--intro` sur les deux. Correctif + test
   `the applicator fills the right body field per activity type`.

== Note de clôture — méthode

La règle du **delta source** a été appliquée : le build compilait à l'ouverture,
aucune suite rejouée « pour confirmer ». Le RED a été prouvé par échec de
compilation à chaque palier. **Le dogfooding a payé une troisième fois**
(S-007 `moodle:4.5`, S-012 `hasRequirement()`, S-013 les trois bugs de
l'applicateur) — et surtout il a **pivoté le design** : la découverte des
outils natifs de l'image (`moosh`, `moodle-blueprint`) a fait abandonner un
script PHP maison qui réimplémentait l'API Moodle (une stack) au profit de
l'appel aux outils préconstruits. Une session de moins aurait livré la mauvaise
architecture.

_Reste ouvert_ : le scaffold compose du service one-shot `moodle-material`
(qui applique `ingest.sh` au premier `compose up`) n'est **pas** livré — il
exige une preuve d'exécution complète `compose up` que cette session n'a pas
produite ; il est documenté comme US suivante plutôt que livré non prouvé
(leçon S-007).
