== Constats (dogfooding)

Le run réel (build `buildAllInstallers` → extraction des heredocs →
`docker compose up`) a prouvé la chaîne **et** découvert 5 écarts :

. *`moodle:4.5` n'existe pas* : `docker compose pull moodle` →
   `pull access denied for moodle, repository does not exist`. Placeholder
   jamais vérifié : le scaffold était inexécutable.
. *Contrat d'environnement faux* : `MOODLE_DATABASE_TYPE/HOST/NAME/PASSWORD`
   n'est exposé par aucune image réelle. Contrat effectif :
   `DB_TYPE/DB_HOST/DB_NAME/DB_USER/DB_PASS` + `MOODLE_USERNAME/PASSWORD/SITENAME`.
. *Version périmée* : le scaffold visait 4.5 ; dernière release **5.2.3**
   (`download.moodle.org/releases/latest`, PHP 8.3, PostgreSQL 16).
. *`portainer/portainer` obsolète* : l'image maintenue est
   `portainer/portainer-ce`.
. *Healthcheck Portainer invalide* : `portainer-ce` est *distroless* (ni `sh`,
   ni `wget`) → `unhealthy` permanent alors que Portainer sert HTTP 200.
. *`cccp-education/academy-workspace:latest` inexistante* : le service
   `workspace` (D-ACADEMY-6-10) ferait échouer `compose up`.

== Décisions de session

. **Le dogfooding a payé** : il a transformé un scaffold « vert en tests »
   mais inexécutable en une machine réellement fonctionnelle (c'est
   exactement la raison d'être d'ACADEMY-6-6).
. **Une image réelle plutôt qu'un placeholder** : `erseco/alpine-moodle`
   embarque Apache+PHP 8.3 et auto-installe au premier boot — indispensable
   pour un `compose up` mono-clic.
. **Suivre le latest** (5.2.3) plutôt qu'une LTS figée — décision pilote.
. **Retirer plutôt que mentir** : le healthcheck Portainer (distroless) et le
   service workspace (image non publiée) sont retirés pour garantir
   l'exécutabilité ; le TODO ACADEMY-5 trace l'insertion future.
