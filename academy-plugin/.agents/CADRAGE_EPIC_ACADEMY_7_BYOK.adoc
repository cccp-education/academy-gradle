== Contexte

ACADEMY-5 est **TERMINÉ (S-009)** : l'agent opencode est exposé au stagiaire
(`opencode.json` + `AGENTS.md` générés, service `workspace` en profile `agent`,
image générée sur `gradle:9.7.1-jdk25`). Mais `opencode.json` câble **un seul
fournisseur** : Ollama embarqué (`http://ollama:11434/v1`, modèle
`gpt-oss:120b-cloud`), en dur dans `OpenCodeConfigGenerator` (constante
`PROVIDER_KEY = "ollama"`).

Le TODO laissé S-009 : rendre `opencode.json` **multi-provider** depuis
`ByokLlmConfig` (contrat N0 `contracts.runtime`, `runtime-contracts:0.0.1`),
sans jamais embarquer la clé — seulement **le nom de la variable
d'environnement** qui la porte.

== Constats (audit S-010 — état réel vérifié, jamais supposé)

. *`render()` est mono-provider structurellement* : `PROVIDER_KEY` est une
   `const val` (`OpenCodeConfigGenerator.kt:22`), utilisée 2× (clé du provider
   et préfixe du `model`). Aucun paramètre ne peut le changer. Le `npm`
   `@ai-sdk/openai-compatible` et le libellé `Academy Ollama (embedded)` sont
   également figés (`:33`, `:36`).
. *`OpenCodeConfig` ne porte aucune notion de fournisseur* : 2 champs
   (`providerUrl`, `model`) — aucune clé API n'est modélisée, ce qui était
   correct en ACADEMY-5 (zéro BYOK) mais bloque ACADEMY-7.
. *Le contrat N0 est publié et réel* (`runtime-contracts:0.0.1`, Maven Central
   HTTP 200, JAR vérifié : `contracts/runtime/ByokLlmConfig.class` +
   `LlmProviderKind.class`) : `ByokLlmConfig(provider, model, baseUrl?,
   apiKeyEnvVar?, poolPorts=11437..11465)` avec invariants — `OLLAMA_LOCAL`
   exige `baseUrl` ; `GEMINI`/`HUGGINGFACE`/`CUSTOM` exigent `apiKeyEnvVar`.
   `LlmProviderKind` = `OLLAMA_LOCAL, OLLAMA_CLOUD, GEMINI, HUGGINGFACE,
   CUSTOM`. Les dépendances transitives (`opencode-session-contracts:0.0.2`,
   `i18n-contracts:0.0.2`) sont sur Central (200) et Kotlin-stdlib est aligné
   (2.4.10, comme le POM du contrat).
. *La syntaxe « clé par variable d'environnement » est officielle opencode*
   (vérifiée docs + schéma `https://opencode.ai/config.json`) :
   `"options": { "apiKey": "{env:ANTHROPIC_API_KEY}" }`. La valeur reste hors
   du fichier : c'est exactement la règle Secrets + BYOK (D-ACADEMY-7-2).
. *Les identifiants de provider réels sont vérifiables* (models.dev `api.json`
   + docs providers, audit S-010 — leçon S-007 `moodle:4.5`, ne jamais
   deviner) : `ollama` (custom, npm `@ai-sdk/openai-compatible`) ;
   `ollama-cloud` (npm `@ai-sdk/openai-compatible`, api
   `https://ollama.com/v1`, env `OLLAMA_API_KEY`) ; `google` **GEMINI** (npm
   `@ai-sdk/google`, env `GOOGLE_API_KEY`/`GEMINI_API_KEY`, pas de baseURL) ;
   `huggingface` (npm `@ai-sdk/openai-compatible`, api
   `https://router.huggingface.co/v1`, env `HF_TOKEN`). `CUSTOM` = provider
   OpenAI-compatible déclaré par l'apprenant (npm `@ai-sdk/openai-compatible`,
   baseURL explicite).
. *La chaîne BYOK a trois maillons cohérents* : (1) `.env` documente le **nom**
   de la variable (valeur vide, jamais commitée — précédent
   `POSTGRES_PASSWORD=`), (2) le compose **transmet** cette variable au service
   `workspace` (`OLLAMA_HOST: ${OLLAMA_HOST}` existe déjà — précédent), (3)
   `opencode.json` la **référence** (`{env:VAR}`). Les trois sont générés,
   zéro secret.
. *Le dogfooding est outillé* : Docker 29.8.1 + Compose v5.5.1 + `jq` 1.7
   présents sur l'hôte S-010 → `docker compose config`, `jq`, `sh -n`
   exécutables réellement (preuve, pas test vert).
. *`poolPorts` est une concern runtime, pas agent* : N0 définit
   `11437..11465` pour la rotation Ollama cloud côté codebase N1
   (`LlmProviderResolver`). opencode parle au endpoint cloud officiel
   `https://ollama.com/v1` — `poolPorts` n'est donc **pas** rendu dans
   `opencode.json` (séparation contrat/runtime).

== Options écartées

- **Garder `PROVIDER_KEY` et ajouter des `when` dans le renderer** : entasse
  la connaissance provider dans le générateur de JSON, sans type testable en
  isolation ; contredit DDD (le domaine `byok` est cohésif). Écartée
  (D-ACADEMY-7-4).
- **Recopier `LlmProviderKind`/`ByokLlmConfig` localement** (split-brain
  N0) : la gouvernance interdit d'introduire un split-brain quand un contrat
  N0 publié existe (leçon RAG-SOCLE). Écartée (D-ACADEMY-7-1).
- **Rendre `poolPorts` dans `opencode.json`** : l'agent opencode ne fait pas
  de rotation de pool — c'est le rôle de `LlmProviderResolver` (codebase N1).
  Écartée (D-ACADEMY-7-9).
- **Rendre `apiKey` littéral ou depuis `.env` par substitution** : embarque ou
  déplace la valeur dans un fichier généré. Contredit la règle Secrets.
  Écartée (D-ACADEMY-7-2).
- **Faire du provider un choix runtime (UI `/connect`)** : la machine
  d'expérimentation est un artefact de build déterministe ; le fournisseur est
  fixé à la génération via l'extension. Écartée.
