== Décisions actées S-014/S-015 (ne pas les rediscuter)

* **Matrice d'engine** (D-ACADEMY-12-1) : Linux = Docker Engine natif (dépôt
  apt officiel) ; Windows = **Docker Desktop** (`install --user --quiet
  --accept-license --backend=wsl-2`, WSL2 **requis et géré par Desktop**) ;
  macOS = **Colima** (`brew install colima docker` + `colima start`).
  **Portainer partout.**
* **Portabilité** (D-ACADEMY-12-5, appliquée S-015) : un `unixScript` unique
  (en-tête par OS, **queue commune verbatim**), un `install.bat`. Un test
  asserte l'égalité de queue Linux/macOS.
* **Décision pure, exécution adapter** (D-ACADEMY-12-2) : domaine `academy.env`
  sans I/O ; `EnvironmentProbe` (fun interface) + `HostEnvironmentProbe`
  adapter = **seul** `ProcessBuilder` de la prod.
* **Verdict, jamais un throw** (D-ACADEMY-12-3, ajusté S-015) :
  `checkContainerEngine` **rapporte** la stratégie, ne fait jamais échouer le
  build — un hôte nu doit configurer/tester (P0 S-014).
* **Reboot assumé** (D-ACADEMY-12-4) : l'activation WSL2 exige admin + reboot
  possible → `.bat` idempotent/resumable (`:bootstrap_wsl2`), jamais promis
  « sans reboot ».
